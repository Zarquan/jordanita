    Locally, we use bash shell scripts to run the build.

    In GitHub workflow, we can use the same shell scripts,
    but the environment is different.

    We want to read the version numbers from the project config file.

    versions.sh reads the config file and sets the values.

    Caveat - potentially the Python version has a datestamp in it.
    Which means the Python version is dynamic.

    Python versions and Java version are created as shell functions
    because they have conditional statements in them.

    Potentially, Python version can have a datestamp.
    So calling the shell function more than once gets a different result.

    We only need to call it once, when we setup the Mavane build to generate
    the Python code.
    The resulting version number is built in to the metadata for the Python
    distribution.

    The only reason for accessing the versions again is if we want to push
    things as GitHub artifacts.

Local shell script

    In a local shell, the environment variables are just there.
    Particularly if we use export.

    In a GitHub workflow ..

        Passing values between runs within a step,
        requires writing them to $GITHUB_ENV.

        Passing values between steps within a workflow,
        requires writing them to $GITHUB_OUTPUT.

    In a GitHub workflow ..

        Why are we splitting the build process into three steps ?
        Because they can be run in parallel ?

    In a GitHub workflow ..

        Why are we splitting this into separate run statements ?
        One single shell script would be a lot easier to manage.

        Some of the conditionals depend on the GitHub status.
        So we do need some separate steps.

    The variables we need to share.

        basepath
        buildpath
        schemapath
        schemashort
        schemaversion
        inputschema

        javaversion
        pythonversion

    The first set are generated from the configuration file, so they don't change.

    In the GitHub actions, we can write all of these to GITHUB_ENV.

    The javaversion and pythonversion should be calculated once and then saved.
    But they only need to be saved for the duration of that job

    For the Java result, we need the javaversion.
    For the Python result, we need the pythonversion.

    In shell script, we can just read them once the versions.sh has been run.
    To make it safer, we can add aan if to prevent them being calculated twice.
