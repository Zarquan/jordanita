    >   All seven issues are fixed, and the build is green. Summary of the changes:
    >   
    >   ## Changes
    >   
    >   **`SimpleComputeResourceQuery.java`** — all six query-side fixes:
    >   1. **Memory unit mismatch** — `DEFAULT_CPU_MEMORY_REQUEST` and `TOTAL_AVAILABLE_CPU_MEMORY` are now plain `Long` GiB values (`1L`, `256L`) instead of `StorageUnits.gibibyte(...)` (whose `.longValue()` returned bytes), and `build()` substitutes them directly. The now-unused `wtf.metio.storageunits` imports were removed.
    >   2. **Dead code** — removed the `HiMemBlocks`, `HiCpuBlocks`, and `CombinedQuery` CTEs (the final `SELECT * FROM EarlyBlocks` was already discarding them), plus the unused `RowCount` column in `AvailableBlocks`. Result-set columns are unchanged.
    >   3. **Block-length truncation** — `:minblocklength`/`:maxblocklength` now round durations **up** to whole blocks with a minimum of 1 (`Math.max(1L, (seconds + 59) / 60)`), so a 30 s request yields a 1-block offer instead of a vacuous 0, and a 61 s request requires 2 blocks.
    >   4. **Unused max limits** — removed `MAXIMUM_START_RANGE`, `MAXIMUM_CPU_CORES_REQUEST`, `MAXIMUM_CPU_MEMORY_REQUEST` (verified: no references anywhere).
    >   5. **Booked-but-unstarted sessions** — `ACCEPTED` added to the phase filter: `phase IN ('ACCEPTED', 'OFFERED', 'PREPARING', 'WAITING', 'RUNNING', 'RELEASING')` (constant name verified against the generated `IvoaSimpleExecutionSessionPhase`).
    >   6. **Typo** — `DATABSE_QUERY` renamed to `DATABASE_QUERY` (declaration + the one use in `build()`).
    >   
    >   **`SimpleComputeResourceEntity.java`** — `fillBean()` now sets the memory bean from `minofferedmemory`/`maxofferedmemory` instead of the cores fields.
    >   
    >   **`SimpleComputeResourceQueryTest.java`** (new) — 9 JUnit 5 tests covering: no leftover placeholders, GiB memory totals (byte value `274877906944` absent), sub-minute rounding to ≥ 1 block, 61 s → 2 blocks, `ACCEPTED` present, dead CTEs absent, defaults (2 h → 120 blocks, `LIMIT 4`), open-ended interval defaulting, and the renamed constant.
    >   
    >   AIMetrics blocks were appended to both modified files and added to the new test per `agents/rules/` (copyright years were already 2026).
    >   
    >   ## Verification
    >   
    >   `source bin/versions.sh config.yaml && ./mvnw -B test` → **BUILD SUCCESS**: 350 main sources compiled, `Tests run: 9, Failures: 0, Errors: 0`. (Note: the first attempt hit a sandbox denial on read-write access to the Maven cache under `/root/.m2`, which I escalated once and confirmed as the cause.)

    >   One thing to flag from the analysis: the query still reads schedule columns on `SimpleExecutionSessions` (`available_start_instant_seconds`/`available_duration_seconds`) that currently have **no writers** in the code — the only writer, `SimpleExecutionSessionEntity.init()`, is commented out.
