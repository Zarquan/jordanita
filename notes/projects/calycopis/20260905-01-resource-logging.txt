    >   Design notes:
    >   
    >       SimpleExecutionSessionEntity is the concrete session entity; SimpleComputeResourceEntity is the (abstract, JOINED-inheritance) compute entity whose maxofferedcores/maxofferedmemory columns live on its own table, so one JPQL query covers both Mock and Docker platform compute rows via WHERE c.session = s.
    >       Each result row is an Object[]: [0] = session UUID, [1] = IvoaSimpleExecutionSessionPhase, [2] = compute UUID, [3] = Long cores, [4] = Long memory.
    >       No SQL ORDER BY: the phase column is @Enumerated(EnumType.STRING), so a DB-level ORDER BY phase would sort alphabetically and cannot produce the required phase sequence. Ordering is applied in the caller (Change 2) using an explicit phase-sequence list.
    >       Sessions without a linked compute resource are excluded by the inner-join semantics (consistent with "the compute resource joined to it").

    >   Implemented and verified. Summary of the changes:
    >   New file
    >   
    >       engine/functional/processing/session/ExpireSessionRequestEntity.java — extends SessionProcessingRequestEntity implements SessionProcessingRequest, @Table("expiresessionrequests"). Behavior:
    >           preProcess: if session is OFFERED and expiry (session.getExpires()) has been reached → set phase EXPIRED and schedule a ReleaseComponentRequest for all session components (executable, compute, data, storage); if still OFFERED but not yet expired → nothing (postProcess decides); any other phase → nothing.
    >           postProcess (re-derives from the persisted phase, since pre/post run in separate transactions): still OFFERED + expiry in the future → activate(DEFAULT_POLL_INTERVAL) (5 s re-schedule); no expiry time → finish; otherwise → done (deletes the request).
    >           DEFAULT_POLL_INTERVAL = Duration.ofSeconds(5).
    >   
    >   Supporting changes
    >   
    >       ProcessingRequestEntity — new activate(Instant) overload so activation can be set to an absolute instant (the session expiry).
    >       SessionProcessingRequestFactory / ...FactoryImpl — new createExpireSessionRequest(session): saves the request and activates it at session.getExpires(), so the queue fires it just after the session expiry.
    >       OfferSetRequestParserImpl.stageTwo — after each new session (offer flow and direct flow) is fully built, schedules its expire request.
    >       LifecycleComponentEntity.getReleaseAction — new INITIALIZING case: releasing a never-prepared component is a clean no-op (previously it hit default and marked the component FAILED); leaves room for future platform-specific release behaviour.
    >       ReleaseComponentRequestEntity.postProcess — INITIALIZING → finish the request (done) instead of falling into default → fail.
    >       UpdateSessionRequestEntity — EXPIRED added to every terminal/skip list, so component-driven updates can never overwrite an expired session.
