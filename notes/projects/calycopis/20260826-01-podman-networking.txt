# Create our configuration files.
#[user@desktop]

    CONFIG_DIR=$(mktemp -d)

    cat > "${CONFIG_DIR}/admin.yaml" << EOF
calycopis:
    admin:
        username: $(pwgen 32 1)
        password: $(pwgen 32 1)
EOF

    cat > "${CONFIG_DIR}/database.yaml" << EOF
spring:
    datasource:
        url: jdbc:postgresql://postgres:5432/calycopis
        username: $(pwgen 32 1)
        password: $(pwgen 32 1)
        driverClassName: org.postgresql.Driver
        initialize: true
EOF

    cat > "${CONFIG_DIR}/spring.yaml" << EOF
spring:
    profiles:
        active: docker
EOF


    yq '.spring.datasource.username' \
       "${CONFIG_DIR}/database.yaml" \
       > "${CONFIG_DIR}/pgusername"

    yq '.spring.datasource.password' \
       "${CONFIG_DIR}/database.yaml" \
       > "${CONFIG_DIR}/pgpassword"

    ?   I want to run two services in separate Podman pods, configured so that they can connect to each other from inside their pods, and are both accessible from the host system.
    ?   If I run the service containers inside a pod, they can connect to each other using their container names as host names, but they are not accessible from outside the pod.
    ?   If I run the service containers without a pod, they are both accessible from the host system using the loop back address and the host's IP address, but the services cannot reach eah other from inside their containers.

    >   Yes. The missing piece is a user-defined Podman network shared by the two pods, combined with port publishing on each pod.

    >                 |                       |
    >            localhost:8080           localhost:5432

    >           |   pod-a   |           |   pod-b   |
    >           | service-a |           | service-b |
    >           +-----+-----+           +-----+-----+
    >                 |                       |
    >                 +---- app-network ------+

    >   Your host claims the entire 10.0.0.0/8 network on enp3s0:
    >   
    >       10.0.0.0/8 dev enp3s0
    >   
    >   and the interface itself is configured as:
    >   
    >       10.12.0.6/8
    >   
    >   So Podman cannot safely auto-allocate any of its usual 10.89.0.0/24-style networks because they all fall inside the host’s directly connected /8.
    >   
    >   For this machine, I would avoid 10.0.0.0/8 entirely for Podman user-defined networks and use part of 172.16.0.0/12 instead, provided you do not
    >   have a VPN or other network using it.
    >   
    >   For example:
    >   
    >       podman network create \
    >           --subnet 172.30.100.0/24 \
    >           calycopis-services
    >   
    >   Given the routing table you showed, that subnet does not currently overlap any host route.
    >   
    >   You can then create the pods on that network:
    >   
    >       podman pod create \
    >           --name service-a-pod \
    >           --network calycopis-services \
    >           --network-alias service-a \
    >           --publish 8080:8080
    >   
    >       podman pod create \
    >           --name service-b-pod \
    >           --network calycopis-services \
    >           --network-alias service-b \
    >           --publish 5432:5432
    >   
    >   The resulting access pattern is:
    >   
    >       Host -> service A:
    >           localhost:8080
    >   
    >       Host -> service B:
    >           localhost:5432
    >   
    >       Pod A -> service B:
    >           service-b:5432
    >   
    >       Pod B -> service A:
    >           service-a:8080
    >   
    >   
    >   One thing I would change longer-term is Podman’s automatic subnet pool, because with a /8 LAN route you
    >   will otherwise keep hitting this whenever you run:
    >   
    >       podman network create some-network
    >   
    >   without specifying --subnet.
    >   
    >   For rootless Podman, you can configure this in:
    >   
    >       ~/.config/containers/containers.conf
    >   
    >   using a pool somewhere in 172.16.0.0/12, for example allocating /24s from a larger reserved block such as 172.30.0.0/16.
    >   The exact default_subnet_pools syntax varies slightly by containers-common/Podman version,
    >   so if you want, I can give you the correct containers.conf entry for your installed Podman version.
