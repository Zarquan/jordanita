# Help from Google AI to setup GitHub branches
#

    ?   How do I setup a local github branch to that I can do the following:
    ?   
    ?   Start with GitHub repository `github-A`
    ?   Created fork GitHub repository `github-B`
    ?   Cloned repository `github-B` to `local-B` on local machine.
    ?   
    ?   Created feature branch `feature-A` in repository `github-A`
    ?   How do I create a `dev-branch-001` branch in `local-B` that is based on `github-A/feature-A`
    ?   Such that commits on `dev-branch-001` are pushed to `github-B/dev-branch-001`
    ?   Then when ready I can create a pull request to merge `github-B/dev-branch-001` into `github-A/feature-A`.
    ?   
    ?   Accumulating small sets of changes in `github-B/dev-branch-001`, `github-B/dev-branch-002`, `github-B/dev-branch-00n`
    ?   Merging them as they are ready to build the full feature in `github-A/feature-A`.

    >   To set up this workflow, you need to configure local-B to talk to both repositories: github-A (usually named upstream) and github-B (usually named origin).
    >   Here is the exact step-by-step terminal workflow to set this up and manage your feature development.
    >   ## Step 1: Link your local repository to both GitHub remotes
    >   Open your terminal in local-B. You need to add github-A as a remote repository so your local machine can see its branches.
    >   
    >      1. Check your current remotes (it should currently just show your fork, github-B):
    >   
    >      git remote -v# You should see 'origin' pointing to github-B
    >   
    >      2. Add github-A as the 'upstream' remote:
    >   
    >      git remote add upstream <URL-to-github-A>
    >   
    >      3. Fetch all the latest branches from both repositories so your local machine is up to date:
    >   
    >      git fetch --all
    >   
    >   
    >   ------------------------------
    >   ## Step 2: Create dev-branch-001 based on github-A/feature-A
    >   Now, create your local branch using the upstream remote branch as the starting point:
    >   
    >   git checkout -b dev-branch-001 upstream/feature-A
    >   
    >   (Alternatively, use git switch -c dev-branch-001 upstream/feature-A)
    >   ------------------------------
    >   ## Step 3: Push changes to your fork (github-B)
    >   When you make commits on dev-branch-001 and want to push them to your fork (github-B), use the -u (set-upstream) flag. This tells Git that even though the branch started from github-A, its push destination should be github-B (origin).
    >   
    >   git push -u origin dev-branch-001
    >   
    >   For all future updates to this specific branch, you can just type git push.
    >   ------------------------------
    >   ## Step 4: Open the Pull Request on GitHub
    >   Once you have pushed your small batch of changes to github-B/dev-branch-001:
    >   
    >      1. Go to your fork page on GitHub (github-B).
    >      2. GitHub will display a yellow banner saying "dev-branch-001 had recent pushes". Click Compare & pull request.
    >      3. In the Pull Request configuration dropdowns, set them exactly like this:
    >      * base repository: github-A | base: feature-A
    >         * head repository: github-B | compare: dev-branch-001
    >   
    >   ------------------------------
    >   ## Step 5: Setting up subsequent branches (dev-branch-002, etc.)
    >   When you are ready to start the next small set of changes, you want to make sure you are basing it on the absolute latest version of github-A/feature-A (which now includes your merged 001 changes).
    >   Run these commands to start the next cycle:
    >   
    >   # 1. Fetch the absolute latest changes from github-A
    >   git fetch upstream
    >   # 2. Create your next branch starting from the updated upstream feature branch
    >   git checkout -b dev-branch-002 upstream/feature-A
    >   # 3. Work, commit, and push it to your fork
    >   git push -u origin dev-branch-002
    >
