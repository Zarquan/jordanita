#1 -----------------------------------------------------

TAP is a set of endpoints that perform operations on tables.

* /sync
* /async
* /tables

The simplest of which is /sync.
POST an ADQL query to /sync the service will execute it.

#2 -----------------------------------------------------

ExecutionBroker is a set of endpoints that manage execution sessions.

* /direct Direct execution (POST, redirect)
* /requests Execution request (POST, redirect)
* /offers/{uuid} Offers response (GET)
* /sessions/{uuid} Session status (GET)

The simplest of which is /direct.
POST a task description and the service will will execute it.

#3 -----------------------------------------------------

The Execution Broker data model describes a re-usable set of components

Executables :
* Docker container
* Jupyter notebook
* etc

Data resources :
* Simple HTTP resource
* Amazon S3 object
* Rucio object
* etc

Storage resources :
* Simple file system
* etc

Task description combines components to describe what you want to do.

#4 -----------------------------------------------------

A simple request to run a Docker container.
```
executable:
  kind: http://purl/docker-container
  image:
    locations:
      - "ghcr.io/zarquan/heliophorus-androcles"
    digest: "sha256:0dfe....4df3"
```

POST this to the /direct endpoint and the platform will run the container.

#5 -----------------------------------------------------

A simple request to run a Jupyter notebook
```
executable:
  kind: http://purl/jupyter-notebook
  notebook:
    location: "http://..../example.jpnb"
```

POST this to the /direct endpoint and the platform will run the notebook.

#6 -----------------------------------------------------

Posting a task with just the executable assumes that the data you want to
work on is already available on the platform.

If not, then we can add a description of the external data resource
we want to use.

```
executable:
  kind: http://purl/docker-container
  image:
    locations:
      - "ghcr.io/zarquan/heliophorus-androcles"
    digest: "sha256:0dfe....4df3"
data:
  - kind: http://purl/simple-data-resource
    location: "http://..../example.dat"
```

#7 -----------------------------------------------------

and we need to add a volume mount to make the data available in the right place

```
executable:
  kind: http://purl/docker-container
  image:
    locations:
      - "ghcr.io/zarquan/heliophorus-androcles"
    digest: "sha256:0dfe....4df3"
compute:
  kind: : http://purl/simple-compute-resource
  volumes:
    - kind: http://purl/simple-volume-mount
      path: /input
      mode: READONLY
      resource: example-data
data:
  - kind: http://purl/simple-data-resource
    meta:
      name: example-data
    location: "http://..../example.dat"
```

#8 -----------------------------------------------------

If this looks familar, it is because the underlying pattern is based on Openstack, Docker, and Kubernetes.

* The kind identifier for types comes from Kubernetes.
* The volume mount pattern comes from Openstack, Docker, and Kubernetes.

but the model is abstracted away from the specific platforms to be able to manage
tasks on a wide range of different platforms, including

* Openstack,
* Docker,
* Kubernetes,
* Slurm,
* Dirac
* Amazon AWS,
* Digital Ocean
* etc ...

#10 -----------------------------------------------------

But in many cases, the end user would not need to create the execution description from scratch.

The developers of the software can supply a template, ivoa-execution.yaml, in their git repository.

```
executable:
  kind: http://purl/docker-container
  image:
    locations:
      - "ghcr.io/zarquan/heliophorus-androcles"
    digest: "sha256:0dfe....4df3"
compute:
  kind: : http://purl/simple-compute-resource
  volumes:
    - kind: http://purl/simple-volume-mount
      path: /input
      mode: READONLY
      resource: example-data
data:
  - kind: http://purl/abstract-data-resource
    meta:
      name: example-data
```

#11 -----------------------------------------------------

The template can be used to build an execution request by replacing the abstract data resource with a specific `simple-data-resource` that contains the URL to download the data from.

Replacing this
```
data:
  - kind: http://purl/abstract-data-resource
    meta:
      name: example-data
```

with this
```
data:
  - kind: http://purl/simple-data-resource
    meta:
      name: example-data
    location: "http://..../example.dat"
```

#15 -----------------------------------------------------

TAP is a set of endpoints that perform operations on tables.
* /sync
* /async
* /tables

The /async endpoint provides asynchronous functionality
to support long running queries.

ExecutionBroker is a set of endpoints that manage execution sessions.

* /direct Direct execution (POST, redirect)
* /requests Execution request (POST, redirect)
* /offers/{uuid} Offers response (GET)
* /sessions/{uuid} Session status (GET)

The /requests and /offers endpoints implement an asynchronous
conversation.

The request and offers interaction allows the user to specify the task they want,
and the service to respond with an offer describing what it can provide.

Q Can you do <this> ?
A YES offers[]

The client or agent displays the offers to the user and lets them
select the one they want to use.


#16 -----------------------------------------------------

New features under development - metrics and costs.

Metrics is a simple way to describe what kind of compute performance
is needed to execute the task.

For eaxmple, the user can use the following metric to request a compute resource
that can reach at least 3.5 on compute-benchmark-21.

```
compute:
  kind: "http://purl/simple-compute-resource"
  metrics:
    - kind: "http://purl/simple-min-max-metric"
      type: "http://purl/compute-benchmark-21"
      min: 3.5
```

The meaning of 3.5 on compute-benchmark-21 is specific to the type of benchmark.
The Execution Broker protocol is merley acting as the messenger.

Request :
Can you provide '3.5 on compute-benchmark-21'

Response :
YES - offers[]
or
NO - "Unable to provide [compute-benchmark-21][3.5]"

#17 -----------------------------------------------------

Metrics are designed to augment the simple compute resource critera
of number of cpu cores and size of memory.

As soon as we start to add high performance GPUs to the mix,
the requirements become complex to describe.
What kind of GPU, how many cores, how much memory, and how is it connected, all influence the performance, but how much depends on the type of task.

We can create benchmarks for specific types of tasks, e.g. cross matching,
source extraction, image processing etc.

If the user wants a better level of performance than their current platform.
They can run the benchmark on their platform, and then set that as the minimum
performance criteria in their request.

```
compute:
  kind: : http://purl/simple-compute-resource
  metrics:
    - kind: http://purl/simple-min-max-metric
      type: http://purl/compute-benchmark-21
      min: 3.5
```

#18 -----------------------------------------------------

If the services include a benchmark metric in their responses, then
it gives the user a more meaningful value to compare offers from
different platforms.

```
compute:
  kind: : http://purl/simple-compute-resource
  metrics:
    - kind: http://purl/simple-min-max-metric
      type: http://purl/compute-benchmark-21
      min: 4.1
```

and

```
compute:
  kind: : http://purl/simple-compute-resource
  metrics:
    - kind: http://purl/simple-min-max-metric
      type: http://purl/compute-benchmark-21
      min: 6.2
```

Is easier to understand the impact of this on their task
than the size of the GPU and memory.

#19 -----------------------------------------------------

Costs.

At least three different providers have mentioned that they have implemented,
or are looking at implementing, some kind of cost for using compute resources.

Not necesarily financial costs, but credits linked to a user account that provide
a way to measure how much compute a user has used, and to encourage them
to think about how many compute resources they request.

Some of our colleagues at UCL are looking at estimating the energy costs of running HPC compute
resources and how to estimate the carbon cost for executing tasks on different platforms.

Adding a costs element to the request and response enables the user and the
service to have a conversation about how much a task will cost, before it is executed.

A user can specify a maximum cost they are willing to incurr to execute a task.
```
compute:
  kind: : http://purl/simple-compute-resource
  costs:
    - kind: http://purl/simple-min-max-cost
      type: http://purl/basic-energy-cost
      max: 0.2
```

A service can declare the minimum and maximum cost that the task will incurr
```
compute:
  kind: : http://purl/simple-compute-resource
  costs:
    - kind: http://purl/simple-min-max-cost
      type: http://purl/basic-energy-cost
      min: 0.05
      max: 0.19
```

#20 -----------------------------------------------------

The metrics and costs can be combined to have a conversation comparing
the level of performance avaiable and costs involved in offers
from different platforms.

The user can describe the required performance and maximum cost they are
willing to incurr.

```
compute:
  kind: : http://purl/simple-compute-resource
  metrics:
    - kind: http://purl/simple-min-max-metric
      type: http://purl/compute-benchmark-21
      min: 3.5
  costs:
    - kind: http://purl/simple-min-max-cost
      type: http://purl/basic-energy-cost
      max: 0.2
    - kind: http://purl/simple-min-max-cost
      type: http://purl/nasa-compute-units
      max: 5
```

The service can respond with the level of performance it can provide
and the costs it will incurr.

```
compute:
  kind: : http://purl/simple-compute-resource
  metrics:
    - kind: http://purl/simple-min-max-metric
      type: http://purl/compute-benchmark-21
      min: 4.1
  costs:
    - kind: http://purl/simple-min-max-cost
      type: http://purl/basic-energy-cost
      min: 0.01
      max: 0.15
    - kind: http://purl/simple-min-max-cost
      type: http://purl/nasa-compute-units
      min: 1
      max: 5
```
