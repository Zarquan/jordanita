    Claude Code Co-Author Commits
    https://explainx.ai/blog/claude-code-commit-co-author-attribution-disable-guide-2026

        While you remain the primary author, Claude Code automatically appends AI
        attribution metadata to the bottom of the commit message body by default.

        It injects a standard Git trailer that looks like this:

            ```
            Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
            ```

        Claude Code exposes direct control over this behavior via `settings.json`.

            ```
            {
              "attribution": {
                "commit": "Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>",
                "pr": "🤖 Generated with [Claude Code](https://claude.ai/claude-code)"
              }
            }
            ```

# -----------------------------------------------------

    United States (USCO Rules)
    https://pec.ac.uk/blog_entries/copyright-protection-in-ai-generated-works/

        No Human Authorship = No Copyright:
        The U.S. Copyright Office requires a human author for a work to qualify
        for copyright protection. Software generated entirely or predominantly
        by AI without substantial human creativity is placed into the public
        domain (meaning anyone can use, copy, or modify it).

        Human-Assisted Code:
        If a human programmer writes architectural designs, edits, refactors,
        heavily structures, or creatively combines AI-generated snippets, the
        human-authored portions can be copyrighted, while the raw AI-generated
        blocks remain unprotected.

        Prompts Alone Are Insufficient: Simply writing a natural-language prompt
        or "vibe coding" an entire application does not grant copyright over the
        resulting code.

    United Kingdom (CDPA 1988 Rules)
    https://www.farrer.co.uk/news-and-insights/protecting-code-and-creativity-software-ip-rights-and-ai-generated-code/

        Computer-Generated Works (Section 9(3)): Unlike the US, the UK Copyright,
        Designs and Patents Act 1988 explicitly recognizes computer-generated works
        (CGWs) that have no traditional human author.

        Who Owns It: Authorship and ownership go to "the person by whom the arrangements
        necessary for the creation of the work are undertaken" (often the person or company
        that ran/directed the AI system).

        gov.uk Copyright and AI: Consultation
        https://www.gov.uk/government/consultations/copyright-and-artificial-intelligence/copyright-and-artificial-intelligence

    Australia
    https://www.nortonrosefulbright.com/en-gb/knowledge/publications/f237e6c7/is-the-output-of-the-generative-ai-system-protected-by-intellectual-property-rights

        Case law has discussed the need for independent intellectual human effort before the
        originality requirement is met.
        This, of course, implies that an author must be human.
        That does not mean that computer assistance is prohibited, but where human input is
        negligible (as it likely would be in generative AI developed materials),
        those Outputs would not attract copyright protection absent significant
        User input to direct the creation process.

        As a consequence, AI-generated Outputs are likely to be public domain.

    The copyright problem with AI-generated code | We Love Open Source • All Things Open
    https://allthingsopen.org/articles/copyright-problem-ai-generated-code-open-source-licenses

        The more you lean on AI to write code for you, the less likely you are to hold
        copyright on the result.
        In the extreme case of “vibe coding,” where you only describe the end product
        and the AI does all the work, you may not be able to claim any copyright at all.

        And because open source licenses rely on copyright, you may not be able to place
        a “vibe coded” project under an open source license, such as the GNU GPL.
